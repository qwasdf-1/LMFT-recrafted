# LMFT-recrafted 26.x validation checklist

## Automated tests

- `.github/workflows/modern-26.3.yml`: Java core tests, Fabric and NeoForge
  26.3 builds, and the full real dedicated-server membership/reload suite.
- `.github/workflows/modern-26.x-compatibility.yml`: the same suite for Fabric
  and NeoForge on 26.1, 26.1.1, 26.1.2 and 26.2, using exact-version builds.
- `modern/26.3/tests/server_integration.py`: standard-library RCON test client
  scoped to an ephemeral CI server (RCON password `lmft_ci_only`).
- `modern/26.3/testdata`: deliberately missing required block entry, missing
  required tag reference, missing optional entry and a NeoForge removal fixture.

The integration probe asserts *actual tag membership*, not merely logs:
1. With a broken tag, `minecraft:stone` is retained and `minecraft:dirt` excluded.
2. Missing required tag references also retain the existing valid block.
3. Missing optional references do not cause warning logs.
4. On NeoForge, a `remove` entry removes `minecraft:stone` while preserving
   `minecraft:dirt`, and an absent optional removal does not warn.
5. `/reload` with the same broken pack logs recovery again.
6. `/reload` after replacing broken entries with valid ones changes the
   effective tag to dirt and emits no new recovery warnings.
7. Reintroducing broken entries and reloading restores valid stone and logs
   recovery again.

The warning-state boolean reset and operator filtering have additional
loader-independent assertions in `TagRecoveryTest.java`.

## Automated multiplayer notification matrix

The live-client workflow `.github/workflows/multiplayer-notifications.yml`
runs on dedicated Fabric and NeoForge 26.3 servers. It uses the 26.3-capable,
MIT-licensed ProtoBot protocol test dependency pinned to Git commit
`71fce9b6f177f3392705f43ae51f7485bb5868d7` in CI only.
Two separately connected, offline-mode Minecraft test clients receive
actual system-chat packets, and RCON promotes one account to operator.
The server binds to 127.0.0.1, uses an ephemeral world, and writes
`lmft.json` before each restart.

Each loader passed four independent server scenarios:

1. **Public:** both nonoperator and operator receive exactly one warning at
   initial join and after each broken reload.
2. **Operator-only:** nonoperators receive none; operator receives one on
   joining and after each broken reload.
3. **Config-disabled:** `disableIngameError=true` suppresses all warning
   packets while recovery and missing-entry logging still execute.
4. **JVM-disabled:** `-Dlmft.disable_error_output=true` suppresses chat
   warnings while recovery and logging remain operational.

Every mode also verifies that a clean reload sends no warning to either
connected player and that reintroducing invalid references reactivates the
expected notification behavior. No unsolicited duplicate warnings occur
between reloads.

**Result: 8/8 multiplayer scenarios passed.**
Evidence: https://github.com/qwasdf-1/LMFT-recrafted/actions/runs/45266710028
