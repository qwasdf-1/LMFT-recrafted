# LMFT-recrafted 26.x validation checklist

## Automated tests

- `.github/workflows/modern-26.3.yml`: Java core tests, Fabric and NeoForge
  26.3 builds, and the full real dedicated-server membership/reload suite.
- `.github/workflows/modern-26.x-compatibility.yml`: the same suite for Fabric
  and NeoForge on 26.1, 26.1.1, 26.1.2 and 26.2, using exact-version builds.
- `modern/26.3/tests/server_integration.py`: standard-library RCON test client
  scoped to an ephemeral CI server (RCON password `lmft_ci_only`).
- `modern/26.3/testdata`: deliberately missing required block entry, missing
  required tag reference, missing optional entry and a NeoForge removal fixture.

The integration probe asserts *actual tag membership*, not merely logs:
1. With a broken tag, `minecraft:stone` is retained and `minecraft:dirt` excluded.
2. Missing required tag references also retain the existing valid block.
3. Missing optional references do not cause warning logs.
4. On NeoForge, a `remove` entry removes `minecraft:stone` while preserving
   `minecraft:dirt`, and an absent optional removal does not warn.
5. `/reload` with the same broken pack logs recovery again.
6. `/reload` after replacing broken entries with valid ones changes the
   effective tag to dirt and emits no new recovery warnings.
7. Reintroducing broken entries and reloading restores valid stone and logs
   recovery again.

The warning-state boolean reset and operator filtering have additional
loader-independent assertions in `TagRecoveryTest.java`.

## Manual multiplayer notification matrix (not automated)

The RCON-only suite has **no connected Minecraft players**, so it does **not**
verify actual chat-packet delivery. Do not claim operator-only notifications
have passed a game-level integration test until this matrix is exercised.

For each loader on a representative release:

1. Start with the broken test datapack installed. Configure
   `config/lmft.json` as
   `{"disableIngameError":false,"showToOnlyPrivileged":false}`.
   Join with an operator and a non-operator account. **Both** should see the
   warning after joining, once the tag issue has been detected.
2. Trigger `/reload` while the pack remains broken. Both connected accounts
   should receive the warning again, with no duplicate spam outside reload.
3. Set `"showToOnlyPrivileged":true`, restart and repeat. **Only the operator**
   should see warnings on join and reload; the non-operator should see none.
4. Set `"disableIngameError":true` and restart. Neither account should receive
   a warning, but skipped entries must still appear in the log.
5. Return to notifications enabled. After a broken reload, remove missing
   references from the datapack and run `/reload`. Neither account should
   receive a warning from the clean reload. Re-introduce the missing entries
   and reload; warnings should resume according to the permission setting.
6. Repeat with `-Dlmft.disable_error_output=true`. This property should
   suppress chat notifications while preserving error recovery and logging.

Configuration is loaded on mod initialization; restart the server after edits.

## Outstanding acceptance gates

- The CI probe checks actual tag contents and reload outcomes, but does not
  directly inspect live `TagRecovery.anyTagsSkipped()` after clean reload.
  Verify clean-reload player notification suppression manually.
- Multi-version runtime tests currently use independently built artifacts.
  A single compiled artifact running across all releases is not yet proven.
- Compatibility with other tag-handling mods and unusual datapack orderings
  needs separate integration coverage.
