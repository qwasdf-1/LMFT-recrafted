# LMFT-recrafted: Minecraft 26.x JAR compatibility audit

Date: 2026-11-23. Status: binary audit **and** cross-loading experiments complete.
Both loaders passed on all five stable 26.x releases with one compiled JAR each.

## Evidence

Compiled artifacts were obtained from successful GitHub Actions runs:

- 26.1, 26.1.1, 26.1.2, 26.2 (Fabric and NeoForge):
  https://github.com/qwasdf-1/LMFT-recrafted/actions/runs/45257979268
- 26.3 Fabric and NeoForge:
  https://github.com/qwasdf-1/LMFT-recrafted/actions/runs/45255530969
- Actual 26.3 server membership and reload tests:
  https://github.com/qwasdf-1/LMFT-recrafted/actions/runs/45260660306

For each loader and version, I unpacked the Actions artifact ZIP, selected the
non-sources mod JAR, hashed its compiled `.class` entries, and compared all
class names and byte contents.

| Loader | Versions | Byte-for-byte class-file result |
|---|---|---|
| Fabric | 26.1, 26.1.1, 26.1.2, 26.2, 26.3 | All 8 compiled classes identical |
| NeoForge | 26.1 and 26.1.1 | Same 8 classes within this group |
| NeoForge | 26.1.2, 26.2, 26.3 | Same 8 classes within this group |
| NeoForge | Compare the two groups | Exactly one changed class: `io/wispforest/lmft/mixin/TagLoaderMixin.class` |

Differences outside the class files:

- Fabric: `fabric.mod.json` and `META-INF/MANIFEST.MF` differ by version.
- NeoForge: `META-INF/neoforge.mods.toml` differs by version.

### The NeoForge annotation difference

Comparing the 26.1 and 26.2 `TagLoaderMixin.class` files using `javap -v`
shows that `@ModifyArg(at=...)` is serialized with a **single** `@At`
annotation on 26.1 but an **array of** `@At` annotations on 26.2.

The target method descriptor, hook target, Java method bodies and other
annotations were unchanged. This appears to reflect a Mixin annotation API
difference between toolchains, rather than a Minecraft tag-loading algorithm
change. We should not assume a class file compiled with one representation
will be interpreted correctly by the other runtime.

### Conclusions

1. **Fabric single-JAR cross-loading PASSED 5/5:** one compiled artifact built
   against 26.3, with version metadata widened for the experiment, passed
   standalone Fabric servers on 26.1, 26.1.1, 26.1.2, 26.2 and 26.3.
2. **NeoForge single-JAR cross-loading PASSED 5/5:** the corresponding 26.3
   artifact also passed on every standalone NeoForge release, including the
   older 26.1/26.1.1 runtime despite the different annotation serialization.
3. Both builds now support an opt-in wide metadata range directly from Gradle.
   Keep exact-version builds in CI and keep 26.4 out of advertised support until tested.
4. None of these differences suggest a meaningful server-tick performance
   impact from unused class files. The issue is class loading/Mixin startup
   correctness and loader metadata, not steady-state CPU cost.

## Universal-JAR experiment results

- Fabric: https://github.com/qwasdf-1/LMFT-recrafted/actions/runs/45262108847
- NeoForge: https://github.com/qwasdf-1/LMFT-recrafted/actions/runs/45262555701

Each built **one** JAR on 26.3, edited only its Minecraft/loader metadata for
the experiment, and used that identical artifact on five separately installed
standalone servers. Every server passed the existing full RCON probe for tag
membership, reloads and optional-entry handling; NeoForge also passed tag
removal assertions. The source was not recompiled per runtime.

## Direct Gradle universal artifacts — tested successfully

After introducing opt-in wide-range metadata, the following CI runs generated
universal JARs **directly from Gradle**, without editing ZIP files after build:

- Fabric Gradle-built candidate: https://github.com/qwasdf-1/LMFT-recrafted/actions/runs/45263167217
- NeoForge Gradle-built candidate: https://github.com/qwasdf-1/LMFT-recrafted/actions/runs/45263166856

Both produced one JAR per loader and each passed 5/5 standalone-server tests
on Minecraft 26.1, 26.1.1, 26.1.2, 26.2 and 26.3. Each test exercised
actual recovered-tag membership, repeated `/reload`, clean reloads,
and NeoForge removal behavior where applicable. The same compiled JAR was
used on all five versions of a given loader.

## Stable release acceptance gates

- **Completed:** Actual connected operator and non-operator join/reload
  warning delivery on Fabric and NeoForge, including suppression modes.
  See https://github.com/qwasdf-1/LMFT-recrafted/actions/runs/45266710028.
- **Release pipeline gate:** test each compiled universal release JAR,
  unchanged, in five standalone Minecraft servers per loader. These tests
  now block the publication workflow instead of relying only on earlier
  one-off cross-loading experiments.
- **Scope limitation:** Broad interoperability with other tag-handling
  mods and unusual third-party datapack layering has not been established.
- Retain version-pinned compatibility CI and fail-fast Mixin checks for
  future versions; Minecraft 26.4 is outside the tested range.

**Single-JAR compatibility is demonstrated for 26.1–26.3, on both loaders;
stable releases enforce those ten exact-artifact server checks.**
